# XEHN 1.0.0

Windows 桌面 UI 重构：C#、WPF、.NET 10 内置 Fluent 主题，橘色强调色。

## 本轮范围

- 首页去掉顶部标题、副标题和品牌标签；连接卡片上移，居中大电源按钮无文字。
- 首页提供紧凑的「代理 / TUN」和「全局 / 分流」分段控件。分流对应 GeoIP / GeoSite 绕过大陆。
- 协议放在设置第一项；主题设置移到设置页，支持浅色、深色、跟随系统。
- 已连接时零速率显示 `0 KB/s`；无流量时保持水平曲线，有流量时只画连续曲线，不在峰值下面叠加横线；历史在 90 秒窗口内右移，断开不清空。
- 不导入旧版 GUI、启动声明弹窗、机器控制码、远程停用名单或自动更新替换逻辑。
- 关于页采用 XEHN、mihomo、GeoFiles、开源与致谢四卡片布局；资源检查与更新规则见下文。
- 保留开源来源与第三方许可证入口。

## 1.0.0：标题栏主题与真实连接检测

- 修复深色切回浅色时原生标题栏仍为黑色：通过 WPF 的 `Application.ThemeMode` 同步 Fluent 主题状态，更新 DWM 属性并重绘非客户区；主题更新队列结束后再核对最新主题。不会激活窗口或改变尺寸、位置、最大化限制。
- 首页和左下角在已接管、仍后台验证时均只显示「已连接」，保留 Progress Ring；严格验证、失败和断开状态不隐藏。
- 原因不是只有文案：此前控制接口就绪便发送「已连接」，但系统代理要等整个验证结束才设置，因此浏览器在那段时间仍未接入。桌面原生协议的快速模式现在先完成一次真实 HTTPS 数据面验证，再接管系统代理、持久化原代理快照及内核 PID，之后才通知界面已连接；后台继续完整载荷验证。验证失败、取消或保存失败均恢复原代理并停止内核；系统代理写入被拦截时不提前宣称已接管，仍保留失败提示。TUN 不改写系统代理。
- 「连接前检查节点可用性」开启时仍在全部验证通过后接管系统代理并显示已连接。热切换也不再在配置重载应答后提前显示连接成功，必须通过真实 HTTPS 和完成目标接管后才显示；失败继续回滚并验证旧连接。旧版 CLI / Psiphon / OpenVPN 出口的独立生命周期不改动。
- 保留原有三个 HTTPS 探测源及出口元数据，每次最多两个并行请求，优先使用先完成的成功响应，并取消、等待较慢请求结束；拒绝访问时仍尝试备用源，保留原 9 秒探测预算。双栈检查并行但两类数据面都须通过。HTTPS 域名请求已证明代理内域名解析，不再串行等待额外的可选 DoH 探测。保留失败重试、完整 128 KiB 载荷和原超时标准；载荷请求及重试等待可以及时取消，不用等待完整超时。并非跳过真实验证，也不承诺所有网络下都有固定的提速幅度。

验证：269 项离线 UI / 工作流及原生窗口检查通过，构建后另核对 3 项真实 EXE 图标；Go 全量测试、vet、11 项引擎桥接及本地构建通过；新增连接回归连续 20 轮及竞态检查通过。新增隔离测试覆盖接管 / 显示 / 载荷验证顺序、严格模式、取消、存储失败及代理恢复、热切换接管后通知、双栈并行与失败、探测并发上限、慢请求取消汇合、截断 / 过大 / 明文响应拒绝、回环 CONNECT 中的载荷取消。标题栏检查覆盖重复深浅切换后的 WPF / DWM 状态和非客户区重绘，不启动真实客户端；当前机器的 Windows 10 不支持 Windows 11 专属标题栏颜色，实机视觉仍需用户复测。未运行真实 VPN / WARP 注册、修改系统代理或测量真实外网检测耗时。

## 1.0.0：热切换验证、资源维护与托盘菜单

- 上次保存的是 TUN 模式时，普通启动也会请求管理员授权，不必先点击连接。取消后保留设置、不重复触发自动连接的 UAC；已经是管理员时不重复启动。
- 提权的 ShellExecute 放在独立 STA 线程，避免阻塞 WPF；启动、握手和内核配置检查有时间上限。热切换不再启动额外的 `mihomo -t` 访问运行中的数据目录，而由控制 API 校验配置。
- 热切换必须完成真实 HTTPS / DNS 数据面验证，不把 API 应答视为连接成功。「连接前检查节点可用性」开启时先显示验证中，成功后才显示已连接；关闭时先显示已连接（检测中）。失败回滚模式并重新验证旧连接；回滚或验证不完整时显示连接异常，允许断开清理，不冒充已连接。切换可取消，IPv6 / 双栈也检查相应数据面。
- 关于页为 2×2 布局。XEHN 卡片仅显示名称、`1.0.0` 与简短的 GitHub 超链接；不展示整条 URL。
- mihomo 卡片显示版本并提供检查。检查会让实际二进制解析 AWG、WG、MASQUE H3/H2、WG / MASQUE 双层与 OpenVPN 共七种配置；无法运行检查也算未通过，不按版本号猜测支持性。
- 内核缺失 / 不支持时显示下载按钮。下载官方最新稳定版的 compatible / baseline 构建，先核对发布资产 SHA256，再解压到暂存区并检查版本及全部协议。**连接时禁用下载安装；后端用进程检查和资源锁再次保护。只有确认旧内核停止后才替换，并按用户要求永久删除被替换的旧内核文件。不会强停 VPN 或覆盖运行中的 EXE。**
- GeoFiles 卡片仅按日显示文件对的上次更新时间；缺失、过小或超过 7×24 小时会提示下载。只检查本地年龄，不宣称与远端版本一致。
- 每次新会话验证成功后以及持续连接期间每小时重新检查 GeoFiles 的本地年龄；过期时自动通过该连接的本地代理下载，代理失败或端口无效不会回退直连。失败最多按新会话 / 小时重试，不逐次轮询重试。先下载到暂存区，校验大小并记录 / 复核暂存文件的 SHA256；已有内核时还解析数据库配置。**不在线替换正在使用的 GeoFiles；断开后或下次连接前再成对替换，保留旧文件对用于回滚。**
- mihomo / GeoFiles 两个卡片分别显示下载进度条和真实字节数；未知总长度使用不定进度。GeoFiles 按当前文件显示进度和文件名。实际替换后在卡片显示成功文本；暂存完成只显示等待断开后替换，不冒充已更新。
- 托盘菜单改为「显示主界面 → 连接 / 关闭 VPN → 退出」。用 WPF 圆角菜单取代旧 WinForms 菜单，无左侧图标占位栏，跟随浅色 / 深色 / 系统主题；关闭的托盘菜单也会刷新主题。

本轮验证：121 项离线 UI / 工作流检查、11 项 C# → Go 桥接检查、`go test -count=1 ./...`、`go vet ./...`、回环 HTTPS / 代理 / 下载和暂存替换测试、本地构建。下载与替换在隔离测试目录中验证，未下载或替换实际使用的内核 / GeoFiles，未触发真实 UAC、自启动注册、系统代理修改或真实 VPN / TUN 测试；尚需用户实机复测代理切 TUN。预览中的下载进度和新版本号是隔离测试的示例数据。

## 连接准备与连接速度（2026-10-30）

- 启动或切换协议后，后台检查所选协议的账号，按需注册；保留已完成的注册，不重复轮换可用凭据。随后检查缓存，缺失、过期或优选强度不匹配时才扫描。
- 首页电源按钮下显示「注册」「优选」两个进度条；未知总量的网络注册阶段使用活动进度，扫描使用真实已处理候选数，不显示虚构百分比。
- 切换协议会取消旧准备任务并串行启动最新任务；准备过程中点击连接，会等待并复用该任务，不再重复注册或扫描。
- 优选强度低 / 中 / 高，默认中；Phase 1 常用端口与备用端口探测分别抽样 4 / 8 / 12 个地址，Phase 2 每子网采样 1 / 3 / 8 个地址，找到 2 / 4 / 8 个符合筛选条件的可用候选后立即取消剩余验证（包括正在等待网络的 Worker）。MASQUE 不进行 WG 的 Phase 1。强度不是速度或质量保证，实际耗时仍取决于网络。
- 扫描使用独立的 Context；提前达到目标不取消后续连接。取消会贯穿握手、隧道 DNS、出口 HTTPS、稳定性 ICMP、延迟测量和 MASQUE CONNECT 响应等待；任务结束后汇合所有扫描 Worker，再释放隧道。
- Phase 2 设置低 / 中 / 高 25 / 45 / 75 秒预算，每个候选（包含同一地址的端口重试）最多 10 / 12 / 15 秒。预算耗尽时停止剩余验证；有可用结果就继续连接，不要求凑满 2 / 4 / 8 个；没有结果则明确报错。该预算不包含注册、Phase 1 或嵌套协议的另一层扫描。空结果不覆盖已有可用缓存，也不作为有效缓存复用。
- 「优选」使用连续的阶段加权总进度，不会在常用端口、备用端口、隧道验证之间归零；嵌套协议为外层和内层保留独立进度区间。百分比表示整个准备流程的阶段进度，文案中的已完成验证、可用、提前跳过数量表示真实任务结果（跳过含取消的在途验证，不记作失败）。切换协议会开始新任务，因此重新计数。
- 首页细分显示缓存检查、候选准备、常用端口、备用端口、外层建链、隧道握手、DNS、出口 HTTPS、稳定性 / 复测、延迟测量、排序和缓存保存；并行验证时显示各子步骤正在处理的数量。
- 「连接前检查节点可用性」默认关闭：核心控制接口就绪后显示「已连接（检测中）」，继续真实数据面验证，失败则立即撤回状态并停止核心。开启后，验证完成才显示连接成功。**系统代理仍在验证成功后接管**，不是跳过检测或承诺此时已有可用网络。
- 有账号、有有效缓存时跳过注册和扫描；桌面连接不重复运行协议能力探测子进程，仍对最终完整配置进行校验。
- MASQUE 的 `handshake-timeout` 已恢复为 5 秒。本轮不继续处理 H2 的连通问题。

### 2026-10-30 扫描回归修复

上一轮 DNS 取消包装隐藏了 UDP 的 `net.PacketConn` 接口，导致 Go 解析器把 UDP DNS 错当成 TCP DNS，加入错误的长度前缀。已用正常应答测试复现旧代码失败，并修复封装；UDP / TCP 接口、UDP 报文格式与真实隔离 netstack 中的成功解析均纳入测试。此前仅测试取消的覆盖不足，不能证明正常解析成功。

MASQUE H3 探测不再直接套用 WG 的 2 秒超时：扫描握手使用 4 秒窗口，并保持可取消；本机 H3 服务延迟 2.1 秒返回成功 CONNECT 的测试通过。**这没有改变 mihomo 配置的 5 秒 `handshake-timeout`，也不等于证明外部网络上的 H3 必然可用。** 新增 DNS / 候选超时 / 整轮预算 / 部分结果保留测试连续运行 20 轮；本轮未运行真实 WARP 扫描或修改系统代理。

## 构建与检查

要求 .NET 10 Windows SDK 和 Go 1.26.3+。构建脚本优先使用仓库 `.cache/toolchains/go1.26.3/go/bin/go.exe`，否则使用 PATH 中的 Go；也可以通过 `-GoExecutable` 指定工具链。此机器的独立工具链来自官方 ZIP，SHA256 已与 go.dev 发布清单核对，不修改系统 Go。

```powershell
# UI 独立构建
& 'C:\Program Files\dotnet\dotnet.exe' build .\src\Xehn.App\Xehn.App.csproj -o .\artifacts\app

# 离线检查和界面预览，不启动连接、不修改系统代理
& 'C:\Program Files\dotnet\dotnet.exe' run --project .\tests\Xehn.Checks -- .\artifacts\previews

# 完整本地构建；可选从原安装目录只复制内核与数据库
.\build.ps1 -CoreSource 'D:\program file\XEHN\core'

# 安全的引擎桥接检查（不连接、不修改系统代理）
& 'C:\Program Files\dotnet\dotnet.exe' run --project .\tests\Xehn.EngineChecks -- .\artifacts\app\engine\xehn-engine.exe .\artifacts\app\data
```

本地构建入口为 `artifacts/app/Xehn.App.exe`。本地副本数据位于该 exe 旁的 `data/`，引擎位于 `engine/xehn-engine.exe`；构建脚本只允许复制 mihomo.exe、geoip.metadb、geosite.dat，**不会复制用户账户、配置、缓存、日志或连接状态**。

除首页接管 / 路由模式热切换外，其他网络设置仍需断开后修改。TUN 会先检查管理员权限并按需请求授权重启。默认关闭窗口后继续在托盘运行；托盘退出或关闭此开关后关闭窗口，会先清理连接。连接进行中可再点击电源取消，等待引擎清理完成。引擎取消通过标准输入传递，不强杀进程以免遗留系统代理。

数据库检查沿用原引擎的文件存在/大小初检，不宣称签名验证或内容解析验证。首次使用分流前会下载缺失的 GeoIP / GeoSite；下载失败则中止连接，不静默降级到全局。
