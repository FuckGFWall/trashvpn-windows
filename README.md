# XEHN 1.0.0

Windows 桌面 UI 重构：C#、WPF、.NET 10 内置 Fluent 主题，橘色强调色。

## 多语言与安装包（2026-11-23）

- 关于页 XEHN 卡片复用原来的「检查」按钮：有新版时原地改为「下载」，不再生成另一个按钮。侧栏「有更新」入口不变。
- 首次按 Windows 界面语言自动选择简体中文、英语或波斯语，其他语言默认英语；在「设置 → 外观 → 语言」可即时切换并保存。波斯语用从右向左布局，底层引擎的原始诊断日志保持原文。
- 运行 `./build-installer.ps1` 在 `artifacts/installer/` 生成 `TrashVPN-1.0.0-Windows-x64-Signed-Setup.exe` 和 `TrashVPN-1.0.0-Windows-x64-Portable.zip`。安装包最低支持 Windows 10 1607（14393），也支持 Windows 11。可以指定 `-InnoSetup`、Windows SDK 的 `-SignTool` 或已有经过检查的 `-CoreSource`；两种包均内含 x64 .NET 运行时及 mihomo/GeoFiles，不复制账户、设置或连接状态。便携版请完整解压到独立目录，再运行 `Xehn.App.exe`；数据保存在同级 `data`，不与安装版共用。若程序目录或现有数据目录缺少写入权限，便携版会通过 Windows UAC 请求以管理员身份重启，并再次检查权限；取消或授权后仍不可写时，提示改用可写目录，不会反复请求。安装版不执行此检查。
- 只需重新打包 ZIP 时可运行 `./build-installer.ps1 -PortableOnly`。构建脚本使用当前用户个人证书库中专用的自签名代码签名证书（首次创建不可导出的私钥），也可用 `-SigningThumbprint` 显式指定已有证书。安装器、卸载器和自有 EXE 使用 SHA-256 Authenticode；只导出公开的 `.cer`，不修改信任设置。自签名不等于 Windows 已信任，SmartScreen 仍可能提示。
- 安装向导按 Windows 界面语言自动选择翻译，首次安装默认使用 `%ProgramFiles%\trashvpn-windows`，可选择独立的空目录。升级同一安装时默认沿用原程序目录，不自动搬迁。首次安装默认勾选「创建桌面快捷方式」和「完成后运行」。新安装将数据存放在 `%LOCALAPPDATA%\trashvpn-windows`，避免与旧版 TrashVPN 的目录发生不区分大小写的冲突。升级时只兼容带本客户端所有权标记的原数据目录。
- 正常卸载移除安装文件；确认永久清理后，额外清理程序拥有的数据目录及安装目录残留。不会递归清理未标记的数据目录、符号链接、目录联接或包含 `.git` 的目录。以其他管理员账号卸载时，也检查本机用户的标准 AppData 路径。

## 应用更新与连接设置（2026-11-23）

- 删除「启动后自动连接」与「连接异常时自动修复」开关；异常修复始终开启，保留「优选完成后自动连接 VPN」与「开机自启动」。连接行为移到外观下方；自定义 DNS 留空时实际使用 `1.1.1.1`，不覆盖手填值或关闭 DNS 的选择。
- 新配置的节点缓存有效期默认为 1 天；已保存的天数及「永不过期」选择保持不变。
- 关于页 XEHN 卡片可检查应用更新。程序比较 GitHub 最新正式 Release 的标签和本地版本；只有版本更高才提供「下载」和侧栏底部的「有更新」入口，点击任意一个都只打开官方下载页，不自动下载或安装。
- 应用运行期间（含托盘）每天按本地日期自动检查一次，必须等 VPN 验证完成，经当前连接的本地代理访问 GitHub，没有直连回退。当天可手动重试；重启保留检查日期和最近一次成功读取的版本。

## 连接与缓存设置（2026-11-17）

- 首页进度条右端增加「就绪」端点及标签，缓存准备成功后与整条进度一起变绿。
- 「允许局域网访问」开启后，其下显示活动网卡的实际 `IP:本地代理端口`；关闭时隐藏，端口和网络变化后更新。优先显示 IPv4，无 IPv4 时使用带方括号的 IPv6；不拿出口 IP 或回环地址冒充局域网地址。是否能从其他设备访问仍取决于连接状态与防火墙。
- 移除 API 端口设置项（内核控制接口仍仅供本机使用，保留已有内部端口）、移除「每次连接重新扫描」设置；旧文件中的该开关不会再强制桌面端每次扫描。首页「重新优选」仍可仅对当前操作强制刷新。
- 新增「优选完成后自动连接 VPN」，默认关闭，与「启动后自动连接」独立。准备成功（包括命中有效缓存）后连接一次；失败、暂停、取消、过期协议任务不会触发，已有手动连接请求不会重复执行，手动断开也不会因此自动重连。
- 新增「缓存永不过期」开关，默认关闭；下一行「缓存有效期（天）」默认 7，开启永不过期后整行变灰并禁止输入，关闭后恢复原有天数。该策略同时用于自动准备、连接、嵌套扫描及节点导出，修改后对已有缓存按原始存储时间重新计算，不会仅改变未来缓存。失败节点标记不延长缓存年龄；永不过期也不会把失败节点变回可用节点。

## 首页统一准备进度（2026-11-17）

- 将注册、优选合并为一根 10 DIP 粗的圆角进度条，注册完成节点位于左侧 1/3，剩余 2/3 映射优选进度。缓存准备成功后整条变绿，左上只显示「缓存已就绪」。
- 工作时左上按「当前大步骤 / 本协议总步骤 操作 · 本步骤实际进度」显示；步骤来自引擎的协议流程计划，WG / AWG 包含端口初筛、MASQUE 跳过该步骤，嵌套协议区分内外层。备用端口是初筛的补充轮次；缓存命中跳过不必执行的步骤。地址数、节点数、可用数与跳过数使用真实扫描事件，不将加权百分比伪装成节点计数。
- 进度上升有平滑过渡，注册 / 优选等待网络时保留流动高光；就绪、暂停、失败及隐藏 / 卸载界面停止动画，并遵循系统减少动画设置。阶段切换、内外层和重试不让总进度倒退；只有主动重新优选或切换协议才开始新的进度。
- 右上提供「暂停 / 继续」「重新优选」。暂停会取消并等待当前网络任务结束，不保留挂起的网络请求；继续复用已经持久化的账号 / 缓存，重新执行未完成扫描。重新优选仅对本次强制刷新，不改变「每次连接重新扫描」偏好。连接排队、内核启动或已连接时禁用这些操作，避免中断连接流程。

## 节点配置导出（2026-11-11）

- 设置页「隧道协议」下方新增「导出节点配置」，右侧为格式下拉框与复制按钮。复制成功后，按钮内显示绿色对勾，2 秒后恢复「复制」；剪贴板写入失败不会显示成功。

- 一次导出所选协议的全部有效缓存节点（去重，排除失败或地址无效的记录），每个节点名称 / tag 包含端点地址以便区分；固定节点不会限制导出范围。嵌套协议导出当前最佳外层端点对应的全部有效内层缓存节点，共享一个外层配置并保留链式引用，不拼接未经优选的内外层组合。缓存缺失、过期、账号未就绪会给出提示，不注册、不扫描、不启动内核、不改变连接或系统代理。

- **导出内容含节点私钥，请勿公开分享。** 不导出注册 API Token / ID、控制端口、系统代理快照或日志；导出结果不进入应用日志，也不写成额外配置文件。复制期间切换协议、格式或设置后，旧结果不会覆盖剪贴板。
- 验证覆盖格式过滤、无导出器时双控件禁用、复制 / 失败反馈与恢复、过期任务、IPv4 / IPv6 / 双栈、密钥与账号数据隔离、只读导出和链式关系；Clash 六种协议配置通过本地 mihomo `-t` 解析检查。离线检查不等同于各第三方客户端的导入、连通或网速验证。

## 连接准备与连接速度（2026-10-30）

- 启动或切换协议后，后台检查所选协议的账号，按需注册；保留已完成的注册，不重复轮换可用凭据。随后检查缓存，缺失、过期或优选强度不匹配时才扫描。
- 首页电源按钮下显示「注册」「优选」两个进度条；未知总量的网络注册阶段使用活动进度，扫描使用真实已处理候选数，不显示虚构百分比。
- 切换协议会取消旧准备任务并串行启动最新任务；准备过程中点击连接，会等待并复用该任务，不再重复注册或扫描。
- 优选强度低 / 中 / 高，默认中；Phase 1 常用端口与备用端口探测分别抽样 4 / 8 / 12 个地址，Phase 2 每子网采样 1 / 3 / 8 个地址，找到 2 / 4 / 8 个符合筛选条件的可用候选后立即取消剩余验证（包括正在等待网络的 Worker）。MASQUE 不进行 WG 的 Phase 1。强度不是速度或质量保证，实际耗时仍取决于网络。
- 扫描使用独立的 Context；提前达到目标不取消后续连接。取消会贯穿握手、隧道 DNS、出口 HTTPS、稳定性 ICMP、延迟测量和 MASQUE CONNECT 响应等待；任务结束后汇合所有扫描 Worker，再释放隧道。
- Phase 2 设置低 / 中 / 高 25 / 45 / 75 秒预算，每个候选（包含同一地址的端口重试）最多 10 / 12 / 15 秒。预算耗尽时停止剩余验证；有可用结果就继续连接，不要求凑满 2 / 4 / 8 个；没有结果则明确报错。该预算不包含注册、Phase 1 或嵌套协议的另一层扫描。空结果不覆盖已有可用缓存，也不作为有效缓存复用。
- 「优选」使用连续的阶段加权总进度，不会在常用端口、备用端口、隧道验证之间归零；嵌套协议为外层和内层保留独立进度区间。百分比表示整个准备流程的阶段进度，文案中的已完成验证、可用、提前跳过数量表示真实任务结果（跳过含取消的在途验证，不记作失败）。切换协议会开始新任务，因此重新计数。

- 「连接前检查节点可用性」默认关闭：核心控制接口就绪后显示「已连接（检测中）」，继续真实数据面验证，失败则立即撤回状态并停止核心。开启后，验证完成才显示连接成功。**系统代理仍在验证成功后接管**，不是跳过检测或承诺此时已有可用网络。

### 2026-10-30 扫描回归修复

上一轮 DNS 取消包装隐藏了 UDP 的 `net.PacketConn` 接口，导致 Go 解析器把 UDP DNS 错当成 TCP DNS，加入错误的长度前缀。已用正常应答测试复现旧代码失败，并修复封装；UDP / TCP 接口、UDP 报文格式与真实隔离 netstack 中的成功解析均纳入测试。此前仅测试取消的覆盖不足，不能证明正常解析成功。

## 构建与检查

要求 .NET 10 Windows SDK 和 Go 1.26.3+。构建脚本优先使用仓库 `.cache/toolchains/go1.26.3/go/bin/go.exe`，否则使用 PATH 中的 Go；也可以通过 `-GoExecutable` 指定工具链。此机器的独立工具链来自官方 ZIP，SHA256 已与 go.dev 发布清单核对，不修改系统 Go。

```powershell
# UI 独立构建
& 'C:\Program Files\dotnet\dotnet.exe' build .\src\Xehn.App\Xehn.App.csproj -o .\artifacts\app

# 离线检查和界面预览，不启动连接、不修改系统代理

# 完整本地构建；可选从原安装目录只复制内核与数据库
.\build.ps1 -CoreSource 'D:\program file\XEHN\core'

# 安全的引擎桥接检查（不连接、不修改系统代理）
& 'C:\Program Files\dotnet\dotnet.exe' run --project .\tests\Xehn.EngineChecks -- .\artifacts\app\engine\xehn-engine.exe .\artifacts\app\data
```

本地构建入口为 `artifacts/app/Xehn.App.exe`。本地副本数据位于该 exe 旁的 `data/`，引擎位于 `engine/xehn-engine.exe`；构建脚本只允许复制 mihomo.exe、geoip.metadb、geosite.dat，**不会复制用户账户、配置、缓存、日志或连接状态**。
